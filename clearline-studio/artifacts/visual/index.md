## Bugs found and fixed during Pass 1 (with evidence)

1. **Mobile horizontal overflow (429px content in a 390px viewport).** First `verify.sh` run flagged this directly (`scrollWidth 429 > clientWidth 390`). Root cause, found by bisection: `.contact-direct` (the "studio@clearline.example — direct, no form required." line) contains the email as one unbroken token with no `overflow-wrap`, so in its narrow grid column (121px) it doesn't wrap and bleeds 67px past its own box — invisible to a per-element `getBoundingClientRect()` scan (zero elements reported `rect.right > innerWidth`) but real, and counted in `document.documentElement.scrollWidth`. Fixed with `overflow-wrap: break-word` on `.contact-direct`. Re-verified: `verify.sh` now reports "Overflow issues: none" at all four viewports.
2. **Six portfolio-plot SVG diagrams appeared blank in the first `verify.sh` run.** Investigated rather than assumed: a targeted script scrolled the page incrementally (real `mouse.wheel` calls) and confirmed every `.plotdraw` element ends at `stroke-dashoffset: 0px` — the diagrams draw correctly for a real user. The blank first screenshot was a **test-tooling artifact**: Playwright's `fullPage` screenshot can render below-the-fold content without physically scrolling the page, so the `IntersectionObserver`-gated draw-on animations never fired during that specific capture. Fixed by rewriting `scripts/verify.js` itself to perform real incremental `mouse.wheel` scrolling before every screenshot, so future evidence in this file is trustworthy rather than a false negative.

## Bugs found and fixed during Pass 2 (interaction + motion review, with evidence)

3. **No persistent contact affordance (C04).** Content read-through found that contact was only reachable by scrolling/dragging all the way to the final section — a real client-trust gap, not just an untested row. Fixed by adding a "Start a line" link docked into the spine itself, visible from any scroll position, wired to the same `springScrollTo()` used everywhere else (not a plain instant anchor jump, to stay consistent with the one motion language). Verified: clicking it from the page-load position scrolled to and settled on `#contact`.
4. **`.crosshair` cursor class was dead code (S05).** CONCEPT.md promises "a fine crosshair with a live coordinate readout," but the CSS class existed and was never applied anywhere in the markup. Fixed by adding it to each `.plot__stage` along with a real `pointermove`-driven coordinate readout mapped to the SVG's own viewBox units — verified mathematically correct (center-of-stage hover produced exactly `"X 150 · Y 150"` for a 300-unit viewBox), not just visually present.
5. **Layout-thrashing read-after-write in `render()` (PF04, found during Pass 1's performance code-review, fixed here).** See QUALITY_GATE.md PF04 for the full detail — `offsetTop`/`offsetHeight` are now cached once in `buildTicks()` instead of being read after a same-frame DOM write on every scroll event.

Two test-script false negatives were also found and corrected **in the test scripts themselves**, not the site, during Pass 2 — recorded here for transparency since they could otherwise look like site bugs to a future reader: a `getComputedStyle(elementHandle, '::after')` call failed because Playwright's `page.evaluate(fn, arg)` doesn't marshal an `ElementHandle` into a raw DOM `Element` the way `getComputedStyle` requires (fixed by querying inside the evaluated function instead); and an hover-state check reported `false` for "visibly different" because the mouse was never moved away between two consecutive `.hover()` calls, so the "before" measurement was actually already-hovered (fixed by explicitly moving the mouse away first).

## Bugs found and fixed during Pass 3 (typography + image + portfolio review, with evidence)

6. **All six portfolio plots shared an identical layout (V02).** Each diagram is genuinely distinct, but the wrapper (text-left/diagram-right, same box size) was identical six times in a row, reading as monotonous under a fresh critical look — exactly the "repetitive section rhythm" the anti-slop checklist warns about, even though no single element was individually generic. Fixed with an alternating `.plot--rev` layout (plots 2/4/6 flip sides on desktop; on mobile the diagram appears before the text instead of after, confirmed via `getBoundingClientRect().top` comparison, not just assumed from the CSS).
7. **The alternation fix itself introduced a real overflow regression (caught immediately, not shipped).** `verify.sh` flagged `scrollWidth 420 > clientWidth 390` on mobile right after adding `.plot--rev`. Root cause: `.plot--rev .plot__grid` (two chained classes, specificity 0-2-0) overrode the mobile media query's single-column collapse `.plot__grid{grid-template-columns:1fr}` (specificity 0-1-0), since CSS specificity beats media-query source order. Fixed by adding an explicit `.plot--rev .plot__grid` override *inside* the mobile media query itself (matching specificity, later in source order, so it wins). Re-verified: `verify.sh` back to "Overflow issues: none."
8. **The core spine position math was wrong for 6 of 9 ticks (found while investigating an earlier "visual only" observation, turned out to be a real functional bug).** `section{position:relative}` is set globally (so plot diagrams' coordinate-readout `<span>` can be absolutely positioned within them), which meant `.plot-N`'s `offsetTop` was relative to `#work` (its nearest positioned ancestor), not the document — incomparable with the top-level sections' document-relative `offsetTop`. This silently corrupted the drag-to-nearest-tick snap target for every plot. Fixed by computing every section's position via `getBoundingClientRect().top + scrollY` instead of trusting `offsetTop` directly. Re-verified: a fresh drag-and-release landed within 0.48px of `plot-2`'s actual top (previously, this exact test would have snapped to a mathematically wrong position).
