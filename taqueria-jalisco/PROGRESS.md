- [DONE] **Pass 1 build + verification.** Built hero, banner-flag nav, food/menu, mural/story, visit sections in one file. `scripts/verify.js` (adapted from clearline-studio's proven runner) confirmed zero overflow, zero console errors across desktop-wide/desktop/tablet/mobile on the first run — but **the screenshots were still actually inspected, not just the automated summary trusted**, and that inspection found two real bugs the automated overflow/console check couldn't have caught:
  1. **Paper-tear geometry bug.** The `.tear` overlay used `inset:0` with a percentage-based clip-path, so on a tall section its "open" residual band (9% of the section's full height) was still on the order of 100+px of opaque paper sitting directly over the section's own heading — confirmed by scrolling to `#food` in a real (non-fullPage) screenshot and seeing "ON THE MENU" rendered as "ON THE .ENU" with the M clipped. Fixed by making `.tear` a fixed-height band (340px, 220px on narrow viewports) instead of `inset:0`, so the residual band stays a genuinely thin strip regardless of section height. Re-verified: the same live screenshot now shows the heading fully clear.
  2. **Mobile wrapping in `.menu-item` and `.visit-row`.** Neither had wrap protection on narrow viewports; the hours table in particular was illegible ("Tuesday7:00\nAM –\n10:00\nPM"). Fixed with `white-space:nowrap` on the value elements plus a `@media (max-width:420px)` rule that stacks label/value vertically instead of forcing a cramped single row. Re-verified via a live mobile screenshot — both now read cleanly, each on its own line.
- [DONE] **A known Playwright tooling artifact was found and root-caused, not mistaken for a site bug.** The fixed-position banner nav appeared to "float" partway down the page in `fullPage:true` screenshots — but direct `boundingBox()` checks at scrollY=0 and scrollY=2000 both confirmed `position:fixed` at `y:0`, and dedicated non-fullPage screenshots at multiple real scroll positions confirmed it renders correctly fixed at the top in every case. This matches this project's established pattern of a `fullPage` screenshot misrepresenting `position:fixed` elements (the element freezes at its last real scroll-relative paint position when the capture fires, rather than its true fixed viewport position) — documented here so it isn't re-investigated as a regression later. `scripts/verify.js` was updated to scroll back to top before the fullPage capture, which did not fully eliminate the visual artifact (the element still appears mid-page, just at a different offset) — the fix that actually matters is *not trusting fullPage screenshots for fixed-position elements* and using targeted screenshots + `boundingBox()` instead, which was done here.
- [DONE] **One originality/specificity gap self-critiqued and fixed.** On review, the concept (papel picado, hand-painted signage) was culturally accurate but generic to "Mexican restaurant" rather than specific to *Jalisco* the state this restaurant is named for. Added an explicit line tying the mural section's agave illustration to Jalisco specifically (birthplace of tequila/agave and mariachi) rather than leaving the connection implicit.
